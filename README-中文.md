# OKX Local — Mac 本地全自动交易测试版

## 先看这里

这是可运行的 **Python + Tkinter 原生窗口源码启动包**，不是已签名/公证的 `.app` 或 `.dmg` 安装器。需要先安装 Python 3.11 或更新版本（带 Tkinter）。不需要云服务器，不连接之前的 Sites 网页。

已实现真实 OKX REST API 下单代码，不是只有按钮的展示页。**开发端没有使用你的密钥，没有发送真实订单，也未在真实 Mac 上完成启动验收或在 OKX 模拟账户完成端到端验收。不要把单元测试通过理解为已验证可安全无人值守实盘。**

默认选择 OKX 模拟盘，默认停止。切换到真实账户后，只有测试连接成功、风险参数校验通过、输入 `LIVE` 确认并启动，程序才可能自动提交真实订单。模式标签以已经连接的账户为准；更换表单环境后必须重新测试连接。

## 1. 安装并启动

1. 解压整个 `OKX-Mac` 文件夹，不要只移动启动文件。
2. 从 [Python 官方 macOS 下载页](https://www.python.org/downloads/macos/) 安装 Python 3.11+、带 Tkinter 的 macOS 安装包，选择适合你的系统的版本。Intel / Apple Silicon 应使用兼容的官方安装包。
3. 双击文件夹内的 `Start.command`。如果 macOS 未允许启动，先核实文件来源；不要关闭 Gatekeeper 或系统安全保护。可使用下方终端方式运行已审阅的源码。
4. 若提示没有执行权限：打开“终端”，输入 `bash `（末尾一个空格），将 `Start.command` 拖进终端，然后回车。
5. 若提示 Tkinter 缺失，使用 python.org 的完整 macOS 安装包。若提示 HTTPS 证书问题，按该安装包的官方说明运行其 `Install Certificates.command`；不要跳过 TLS 验证。

此包不自动安装依赖、不下载并执行远程脚本。Python 标准库之外没有第三方依赖。

## 2. 连接 OKX

在“① 连接 OKX”填写：

- 账户官方 API 域名：必须与账户所属平台一致；默认 `www.okx.com`，不是代理地址。只有官方域名白名单可选。
- 环境：先选择“OKX模拟盘”，使用在 OKX 模拟交易里创建的独立 API 密钥；它与实盘密钥不同。
- API Key、Secret Key、Passphrase：仅在本机填写，不发到聊天、不截图分享。
- 点击“测试连接（只读）”，查看账户环境、持仓模式、USDT权益和BTC持仓。

只读测试不改变账户模式、杠杆或挂单。自动交易要求 `trade` 权限，程序拒绝包含 `withdraw` 权限的密钥。请尽可能关闭其他不需要的权限。

密钥只保存在进程内存中，不写入设置或日志；退出后需要重新填写。不能防御已经被恶意软件控制的电脑，使用后不要把密钥留在剪贴板。

你不租服务器也可以在本机运行。如果账户允许创建不绑定IP的API，可以按OKX设置使用，但这样失去了IP访问限制；支持绑定固定出口IP时应绑定。程序不修改OKX白名单，也不会替你绕过地区、合约资格或API权限限制。特别注意：服务器所在地或本机IP不能使原本不具备资格的账户获得交易权限。

## 3. 必要的账户准备

- 使用 **专用子账户**；同一子账户不要同时手动交易或运行其他机器人。
- 本版本仅支持 **BTC-USDT-SWAP、USDT线性永续、双向持仓模式**。
- 在 OKX 自行设好双向持仓。程序不自动修改账户持仓模式。
- 第一次启动前，BTC不能有已有仓位、普通挂单或止盈止损策略挂单。
- 所有本程序开仓都发送 `tdMode=isolated`。每次开仓前只设置当前方向的逐仓杠杆，并读取验证；不转为全仓。

## 4. 风险参数

在“② 风险设置”填写并保存。默认数字只是用于演示，**并不是针对你的资金建议**。

| 参数 | 含义 |
| --- | --- |
| 资金预算 | 用于计算风险和保证金上限，不会自动转入资金，也不隔离实际账户余额 |
| 最大名义仓位 | BTC数量乘价格；不是保证金金额 |
| 逐仓杠杆 | 首版支持1—10倍 |
| 单笔USDT风险 / 百分比风险 | 两者取较小值，同时受剩余日亏损预算限制；首版不超过预算资金的5% |
| 日内权益回撤 | 按UTC日累计、以程序观测的USDT权益峰值衡量，包括浮亏及资金费；不是单纯已实现亏损 |
| 连续亏损次数 | 按一次仓位归零前后的USDT权益变化判定，包含费用与外部资金变化；UTC换日重置 |
| 冷却时间 | 一次平仓或FOK取消后暂停再开仓的分钟数 |
| ATR止损倍数 | 1小时ATR14的0.6—3倍 |
| 止盈R | 止盈距离为止损距离的1—5倍；一个目标全平 |
| 单边手续费预算 | bps单位；10bps=0.1%。由你按账户费率设足，不会自动读取费率等级 |
| 限价偏移 / 滑点预算 | 用于FOK入场限价和风险估算。真实止损滑点可能超过估算 |

风险上限是 **开仓预算和停止新开仓的阈值，不是最大实际损失承诺**。跳空、流动性、网络故障、资金费和止损成交延迟都可能使实际损失更大。

运行中编辑输入框不会改变当前执行器；先停止，再保存并重新确认启动。已有仓位的止盈止损不会被新设置改写。

## 5. 全自动逻辑

1. 程序每轮读取最新行情，正常网络下约5秒轮询，REST请求耗时可能延长周期；不是逐笔WebSocket行情。
2. 读取至少1000根已收盘K线作为EMA预热，检测缺口和过期数据；未收盘K线不参与信号。
3. 1小时EMA200、EMA20/50排列和斜率、RSI决定方向。
4. 15分钟回到EMA20附近，真实K/D交叉及RSI共同确认；不把“K大于D”误认为当根金叉。
5. 条件未全部满足时观望。严格过滤可能长时间没有订单，不会为了成交强行开仓。
6. 按风险与合约实时 `ctVal / lotSz / minSz / tickSz` 向下取整计算张数；小于最小数量则跳过。
7. 开仓使用 **FOK限价单**：价格和数量不能全部成交时取消，不追价、不补仓。本地先保存唯一订单编号和信号K线编号，再发送请求。
8. 每个开仓请求都附带 **一个市价触发止盈 + 一个市价触发止损**，触发价类型为最新成交价 `last`。
9. 订单请求成功不等于成交。程序读取订单状态、逐仓持仓以及交易所保护单，核对数量、方向、止盈止损价格和保护单编号。
10. 如果保护单状态在提交15秒后仍无法核实，立即关闭新开仓并报警，**不会假装保护已生效，也不会不加确认地另发平仓单**。请立即在OKX核对/平仓。网络轮询耗时会使发现时间超过15秒。

策略由固定规则执行；**未调用GPT或Gemini，不包含AI胜率预测，也未证明盈利能力**。Bollinger、EMA、KDJ、RSI、ATR全部显示；Bollinger在这一版用于展示上下轨和中轨，不单独作为入场触发。与先前文字策略不同：不采用8分投票；实盘止损按你设置的ATR倍数，不按人工挑选的结构点；止盈不分批。可审计的规则见 `core.py` 与 `engine.py`。

## 6. 使用顺序

1. 在OKX模拟盘创建密钥，填入并测试连接。
2. 确认账户与参数，启动全自动时输入 `DEMO`。需要符合策略才会产生模拟账户订单。
3. 在OKX模拟盘逐项核对方向、逐仓、张数、实际成交、止盈止损生效、触发后的平仓、重复启动和异常停机。
4. **完成以上验收后**，如你决定使用实盘，停止并清空模拟账户连接，选择“真实账户”，用实盘密钥重新测试连接。
5. 输入风险参数，点击“启动全自动”，阅读全部授权摘要并输入 `LIVE`。此后符合策略的订单不逐笔征求确认。

程序启动、重启或故障恢复后，均不会自行恢复开仓，必须由你重新启动。

## 7. 停止、平仓与故障

- “停止新开仓”：不再发新的开仓单；继续核对本程序已记录的订单与持仓。不会撤掉原有TP/SL，也无法撤回已发送的请求。
- “仅平本程序仓位”：二次确认后，以同一 `posSide` 的反向操作平当前逐仓仓位，不开相反方向的新仓。网络不确定时不重复发送。
- “核对后解除故障锁”：只有账户BTC仓位、普通/策略挂单全部为空且原记录订单能核实为终态才允许解除；不会删除日亏损基准或随意重置亏损次数。
- 下单超时：不要反复点击。去OKX查订单，客户端编号可从本地状态文件获取；结果未知时程序会保留锁。
- 确定性拒单也可能留下保守锁：如果原客户端编号始终查不到，首版不会自动解除。保留状态文件和脱敏错误码，停止使用并诊断；不要删文件绕过锁。
- 电脑关机、睡眠或断网后本地程序不能工作。只有已经在OKX生效的保护单不依赖电脑继续运行；未生效的保护单不受此保证。
- 日回撤达到上限只停新开仓，已有仓位继续依靠原保护单退出，不立即强制平仓。
- 必须同时能够访问OKX官方网页/App，准备人工处理。不要将该待验收版本无人值守运行。

## 8. 本机数据

默认保存在 `~/Library/Application Support/OKXLocal/`：

- `settings.json`：不含密钥的风险参数。
- 账户哈希对应的 `.json`：活动订单、故障锁、冷却、日内基准和去重状态。
- `.history.jsonl`：提交、取消、仓位归零记录。
- `events.log`：脱敏事件/报警。不会记录API密钥。
- `instance.lock`：阻止同一Mac用户同时运行两份程序。

不要在有仓位或未知订单时删除状态文件。它们用于避免重复下单。API密钥更换后，同一账户的状态仍保留。另一台电脑上的实例无法被这台电脑的锁阻止，不要多机共用同一账户。

## 9. 测试和限制

运行 `python3 -m unittest -v test_engine` 可以执行模拟接口测试；不会连接OKX或产生订单。

详见 `TEST-REPORT.md`。本包没有完成真实Mac视觉验证、OKX模拟盘端到端、实盘成交/止损触发测试、第三方安全审计或历史收益回测。保护单字段/账户资格等必须以你账户上的当前OKX接口为准；接口不兼容时程序停止而不是降级为无保护订单。

本软件不是OKX官方产品；没有提币、转账、借贷接口，也没有联网模型调用。
